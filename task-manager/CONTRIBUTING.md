# Contributing Guidelines

## Branch Naming Convention

- `feature/member1-core` - Core functionality
- `feature/member2-ui` - UI and styling
- `feature/member3-features` - Additional features

## Commit Message Format

```
Add: Brief description of what you added
Update: Brief description of what you updated
Fix: Brief description of what you fixed
```

## Pull Request Process

1. Create your feature branch from `main`
2. Work on your assigned files only
3. Test your changes locally
4. Commit with clear messages
5. Push to your branch
6. Create Pull Request on GitHub
7. Request review from at least 1 team member
8. Address review comments if any
9. Wait for approval and merge

## Code Style

- Use meaningful variable names
- Add comments for complex logic
- Keep functions small and focused
- Use consistent indentation (2 spaces)

## Testing Before Push

- Run `npm start` and verify the app works
- Check console for errors
- Test on different screen sizes (if working on UI)

## Communication

- Use GitHub Issues for bugs/features
- Tag team members in PR comments
- Update status on project board
